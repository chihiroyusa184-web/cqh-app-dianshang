# mall-system 电商促销系统

软件工程实验一和实验二的共同项目。项目经理：柴清会。

仓库：https://github.com/chihiroyusa184-web/cqh-app-dianshang

## 开发协作

完整的[开发任务说明](docs/developer-task.md)包含老师两份材料对应的任务、验收标准和协作节点。A部分从`main`创建`dev`实现商品搜索，提交`dev → main`的PR；项目经理合并A并准备`develop`后，B部分从`develop`创建`feature/coupon-calc`实现最优券推荐，配合冲突与Review演练，提交PR合入`develop`，再由项目经理组织发布。

商品区支持按商品名称搜索：输入关键词后点击“搜索”，名称包含关键词的商品会显示；英文匹配忽略大小写，首尾空格会被忽略。点击“清空”恢复全部商品。搜索仅筛选展示列表，不改变库存、订单或购物车中已填写的数量。后端对应接口为`GET /api/products?keyword=关键词`。

最优券推荐留给开发人员实现。当前优惠券通过手工输入计算。

## 运行

安装Node.js 20或更高版本，无第三方依赖，无需执行npm install。在本目录运行：

```powershell
node server.js
```

打开 http://127.0.0.1:3000 。终端显示本次随机生成的管理令牌，复制到网页的运营管理区即可查看订单、统计和维护优惠券。令牌不写入代码或Git仓库；也可通过环境变量MANAGER_KEY指定。令牌会在未指定环境变量时随重启变化。

```powershell
node --test
node scripts/demo.mjs
```

第一条执行自动化测试；第二条在临时数据库完成真实HTTP下单演示，退出后自动清理，不影响网页演示的数据。

## 建议演示

1. 机械键盘数量输入2，券码输入SAVE20，点击计算优惠：原价258元、优惠20元、应付238元。
2. 在商品搜索框输入“键盘”并搜索，只显示机械键盘；清空后恢复全部商品，键盘数量仍为2。
3. 创建订单，库存从20降为18。
4. 输入终端管理令牌，刷新统计与订单：订单1笔、商品2件、应付合计238元。
5. 使用EXPIRED，查看过期提示；键盘数量1并使用SAVE20，查看未达门槛提示。
6. 在运营管理中新增CLASS10券，门槛10000分、满减1000分，再重新计算。

金额全部按整数分传输；数量为1至99的整数；重复商品会先合并校验。OFF10表示优惠10%即九折，满100元可用，优惠最多30元。一次只能使用一张优惠券。

## 目录及边界

- `server.js`：HTTP路由、管理令牌检查和统一错误处理。
- `src/domain.js`：商品校验、优惠计算、下单、统计等处理过程。
- `src/store.js`：单进程串行事务和JSON文件持久化。
- `public/index.html`：购物及运营页面。
- `test/system.test.js`：业务边界及HTTP集成测试。
- `data/store.json`：首次启动生成，已列入.gitignore。

本系统是本机课堂原型，监听127.0.0.1。订单状态是“已创建”，没有支付、退款、物流或用户账户功能。JSON存储的串行事务适用于单进程，不支持多个服务进程共享写同一文件，也不承诺数据库级断电恢复。管理令牌仅为原型的接口访问控制，不等同于完整用户权限系统。
